# Independent app identity and first-run import

Pipeup uses the Tauri identifier `com.azhurb.pipeup`, the native executable `pipeup`, the database `pipeup.db`, and the OS credential service `com.azhurb.pipeup`. These names separate installation, local data, single-instance handling, and credentials from OpenTypeless. macOS release builds use the `Pipeup Release` signing certificate. A new macOS identity requires its own Microphone and Accessibility grants.

Older Pipeup builds and upstream OpenTypeless used `com.opentypeless.app`. Their data may therefore occupy the same legacy directory. Pipeup cannot tell which app last wrote it. On first launch, if the new Pipeup directory has no settings, database, credentials, or prior import decision and the legacy directory contains supported data, the main window offers **Import a copy** or **Start fresh**. The choice happens before Pipeup opens its stores or registers its global shortcut. Neither choice changes the legacy directory or removes the old app.

The import snapshots the old SQLite database with `VACUUM INTO`, checks its integrity and expected tables, and copies it as `pipeup.db`. It copies `settings.json` and any `credentials.json` into the new directory. The imported `auto_start` setting is turned off so two installed apps do not begin competing at login. On Windows and Linux, known provider keys are also copied from the legacy OS credential service into Pipeup's service where readable; an unavailable store or rejected write is reported without exposing a key to the frontend. On macOS, current builds use the owner-only credential file, which is copied with `0600` permissions. Older Keychain-only credentials may need to be entered again.

The import stages files before placing them in the new directory. It refuses to overwrite Pipeup data. A failed or incompatible database import reports an error and allows the user to retry or start fresh. The final choice is recorded in `identity-migration.json`, and the app restarts before normal startup so the copied settings, database, and credentials are loaded together. This is a one-time copy, not ongoing synchronization. Fresh Pipeup settings use a different default shortcut from OpenTypeless. Imported settings retain their saved shortcut, so users running both apps may need to change one.

See [Storage](storage.md) for current file and credential formats, [Troubleshooting](../references/troubleshooting.md) for macOS permissions, and [Release preparation](../references/release-preparation.md) for packaged upgrade checks.
